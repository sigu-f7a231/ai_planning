# 無料で試すAIアプリポートフォリオ

Copilotを開発パートナーとして活用し、LLMアプリのフレームワークやライブラリーの特徴を、小さなアプリを通して学ぶポートフォリオです。

各アプリは**独立したプロジェクト／GitHubリポジトリ**として作成し、Docker環境も分けます。このREADMEはポートフォリオ全体の紹介用です。

まずは**追加費用をかけずにローカルで動くMVPを作る**ことを目標にします。LLM APIを使わないと動かない設計にはせず、ローカルモデルやモックデータでも基本機能を確認できるようにします。

> **開発状況:** 企画・設計段階。各アプリはこれから実装します。

## このポートフォリオで実現したいこと

6つのAI開発ツールを使い、似た課題を異なる方法で解決する小規模なアプリを作ります。単にツールを使った実績を並べるのではなく、**課題に合わせて技術を選び、AIと協働して実装し、テストで品質と限界を確かめられること**を一貫して示すのがゴールです。

- まずは自分のPCで動くMVPを完成させ、常時公開や多人数利用は後回しにします。
- 各アプリの主役となる技術的な学びをひとつに絞り、過剰な機能を避けます。
- Copilotは調査・設計案・実装・テストの補助に使います。要件、採用判断、生成結果の確認、完成判定は自分で行います。
- 動作する画面だけでなく、データの流れ、テスト結果、失敗時の挙動、採用理由と制約も説明できる状態を目指します。
- 既存サービスに勝つことは目的にしません。似た利用者課題を知ったうえで、学習目的に合わせて範囲を絞ります。

### 6つのアプリで試すこと

| アプリ | 似た利用者課題の例 | この作品で特に確かめること |
|---|---|---|
| Dify FAQボット | ChatbaseやIntercom Finのような、資料に基づく問い合わせ対応 | 回答の根拠を示し、資料外の質問に推測で答えない小規模なRAG |
| LlamaIndexメモ検索 | NotebookLMのような、持ち込んだ資料の検索・質問応答 | 文書取り込みから検索・出典表示までをコードで構成し、検索品質を評価 |
| LangChain家計CSV説明 | データ分析・家計管理サービスの支出把握 | 金額計算は通常のコードに任せ、LLMは集計結果の説明に限定 |
| LangGraph○×クイズ | Quizletなどの学習・復習 | 正誤に応じる状態遷移、ヒント、再回答、終了処理 |
| CrewAIお出かけプラン | Mindtripなどのお出かけ・旅行計画 | 2役の協力が1役より有効かを、品質・時間・呼び出し回数で比較 |
| Pydantic AI買い物リスト | AnyListやBring!などの買い物リスト | 自然文を型付きデータにし、曖昧さや不正な出力を安全に扱う |

これらの既存サービスは課題を理解するための参考例であり、機能を再現したり、すべてがAIを使う直接の競合だと主張したりするものではありません。

## 共通の技術・データ方針

- Dify以外の5アプリは**Python＋Streamlit**を基本にします。画面作りより、各ライブラリーの特徴を動く形で学ぶことを優先します。
- それぞれ独立したプロジェクト／GitHubリポジトリ／Docker Compose環境にします。依存関係、ポート、環境変数、volumeを共有しません。
- Dockerはホストの開発環境を分けるために使いますが、LLM APIやクラウドの費用まで無料にするものではありません。
- コード、README、架空または公開可能なサンプル、テスト用データは各アプリのGitHubリポジトリで管理します。
- APIキーは`.env`などGit管理外に置き、実データ、ログ、SQLite、キャッシュ、生成インデックスは公開リポジトリに含めません。
- DifyのナレッジベースとLlamaIndexの検索インデックスは原本ではなく、原本から作る検索用データとして扱います。
- データベースや外部公開はMVPに必要な場合だけ追加します。初期版はメモリー、ローカルファイル、専用Docker volumeを優先します。

### 無料で進めるときの前提

ここでいう「無料」は、**追加の現金支出をできるだけ避けてローカルの学習用MVPを作ること**です。Copilotの契約料、既存PCの購入費・電気代、作業時間は含めません。LLM API、クラウドサービス、ホスティング、Docker利用条件は別途確認が必要です。

LLMを利用できる無料枠があるとは限らず、無料枠の上限や規約も変わります。利用前に公式情報を確認し、支払い設定と利用上限を把握します。使えるモデルがない場合は、ローカルモデル、固定データ、テンプレート、モックで基礎機能を作り、**モックで確認したことと実LLMで確認したことを区別して記録**します。モックだけの動作を実LLMの検証済みとして扱いません。

## 開発の進め方とスプリント

各アプリを1人で開発し、Copilotと相談しながら進めます。**1SPは2週間・10営業日、1日2〜3時間程度**を目安とします。すべてを1SPで完成させる前提にはせず、難しい技術検証やモデル接続が残る場合は、基礎MVPとLLM・品質評価を分けます。

| 順番 | アプリ | SP1で行うこと | SP2で行うこと |
|---:|---|---|---|
| 1 | Dify FAQボット | Cloud／セルフホストの条件確認、架空FAQ登録、基本的な検索・回答の確認 | 引用、資料外・曖昧質問への対応、テスト・改善、READMEとデモ |
| 2 | LlamaIndexメモ検索 | Docker、Markdown取り込み、検索・出典表示、再インデックス、検索テスト | LLM回答、根拠不足時の抑制、検索品質評価 |
| 3 | Pydantic AI買い物リスト | スキーマ、固定応答による構造化、検証、画面、異常系テスト | 利用可能なLLM接続、曖昧入力の確認フロー、評価とREADME |
| 4 | LangChain家計CSV説明 | CSV検証、正確な集計、限定質問、テンプレート説明、画面 | LLMによる説明、失敗時処理、LLMあり／なし比較 |
| 5 | LangGraph○×クイズ | 問題データ、状態遷移、主要分岐のテスト | Streamlit画面、ヒント・進捗・再スタート、デモ |
| 6 | CrewAIお出かけプラン | モックによる2役の連携、条件不一致処理、画面 | 実LLM接続と1役／2役比較（無料枠等が使える場合） |

各SPの完了条件は、機能が動くことだけではありません。テスト、README、制約の説明、モック／実LLMの検証範囲を含めます。SP1で予定の範囲に届かなければ、新機能を増やさず未完了の基礎作業を次SPの先頭に移します。SP2でも環境や無料枠の条件が満たせない場合は、有料利用へ進まず、未検証事項を明示します。3SP目以降は、MVP完成後に必要性を確認した改善だけを対象にします。

### 全アプリ共通の完了イメージ

1. 独立したDocker環境で起動でき、基本操作を確認できる。
2. 受け入れ条件に沿った正常系・異常系のテストまたは手動評価を行っている。
3. READMEに目的、使い方、データの扱い、技術を選んだ理由、制約を記載している。
4. 実LLM・ローカルモデル・モックのどれで検証したかを明記している。
5. デモを行える状態で、未実装・未検証の範囲を誠実に説明できる。

## 1. Dify FAQボット

### 概要

架空の店舗やサービスについて、営業時間・返品ルール・問い合わせ先などのFAQを登録し、質問に回答します。資料に答えが見つからない場合は、推測せず「資料に情報がありません」と案内します。

### データの置き場所

- **原本:** `dify-faq-portfolio`リポジトリの`knowledge/`にMarkdownで保存し、GitHubで変更履歴を管理します。
- **検索用データ:** 原本をDifyのナレッジベースにアップロードします。
- **同期方法:** 最初は手動アップロードとし、資料を更新したらDify側も更新します。

```text
dify-faq-portfolio/
├── README.md
├── knowledge/
│   ├── shop-hours.md
│   ├── returns.md
│   └── contact.md
└── workflow/
    └── export.yml
```

### 無料で作る範囲

FAQを5〜10件に限定し、Difyの無料利用枠またはセルフホストを検討します。回答に使うLLMの料金は別になる場合があるため、利用するモデルと無料枠を事前に確認します。モック資料には架空の情報だけを使います。

## 2. LlamaIndexメモ検索アプリ

### 概要

短いメモをいくつか登録し、質問に関連するメモを検索して、根拠と一緒に回答します。関連する情報がない質問には回答を控えます。

### データの置き場所

- **原本・評価用質問:** `llamaindex-notes-search`リポジトリの`data/`と`tests/`に保存します。
- **検索インデックス:** ローカルで生成し、原本から再作成できるようにします。
- **会話履歴:** 必要になった場合のみ、ローカルのSQLiteに保存します。

```text
llamaindex-notes-search/
├── README.md
├── data/
│   └── notes/
│       ├── travel.md
│       └── study.md
└── tests/
    └── questions.json
```

### 無料で作る範囲

数件のテキストメモから始め、ローカルの埋め込み・LLMモデルまたは利用可能な無料枠を使います。大量のPDF解析やクラウド処理は初期版の対象外です。

## 3. LangChain家計CSV説明アプリ

### 概要

架空の家計簿CSVを読み込み、カテゴリ別の支出を集計します。「最も支出が多いカテゴリは？」などの質問に、集計結果をもとに回答します。

### データの置き場所

- **サンプルCSV・カテゴリ定義:** `langchain-budget-analyzer`リポジトリの`data/`に保存します。
- **集計結果:** 実行時に計算し、原則として永続保存しません。
- **ユーザーが追加した記録:** 保存が必要になった場合のみ、ローカルSQLiteを使います。

```text
langchain-budget/
├── README.md
└── data/
    ├── sample-expenses.csv
    └── categories.json
```

### 無料で作る範囲

金額計算はPythonなど通常のコードで行い、LLMには集計結果の説明だけを任せます。まずはサンプルCSVと固定文の説明で完成させ、無料で使えるローカルモデル等が利用できる場合に生成機能を追加します。個人の家計データはGitHubに置きません。

## 4. LangGraph○×クイズ

### 概要

問題に回答し、正解なら次の問題へ、不正解ならヒントを表示します。問題番号や正解数を保持します。

### データの置き場所

- **問題・正解・ヒント:** `langgraph-quiz`リポジトリの`data/questions.json`に保存します。
- **進行状況:** 簡単な試作ではメモリー上に保持し、再起動後も続ける場合はローカルSQLiteに保存します。

```text
langgraph-quiz/
├── README.md
└── data/
    └── questions.json
```

### 無料で作る範囲

問題は自作の固定データとし、LLMを使わずに状態遷移と分岐を実装します。まず「正解なら次へ、不正解ならヒント」の動きを確認します。

## 5. CrewAIお出かけプラン作成

### 概要

入力された条件を受けて、「行き先候補を出す役」と「候補を整理してプランにする役」が順番に作業します。

### データの置き場所

- **架空の候補地・条件:** `crewai-trip-planner`リポジトリの`data/`にJSONで保存します。
- **役割間の入出力・実行ログ:** ローカルに保存し、公開するデモ出力は個人情報を含まない内容にします。

```text
crewai-trip/
├── README.md
└── data/
    ├── destinations.json
    └── sample-requests.json
```

### 無料で作る範囲

まずは2役・小さな入力に限定します。ローカルモデルが使える環境なら接続し、難しい場合は固定応答でタスクの受け渡しを検証します。その場合、READMEに「実LLMによる生成ではなく、フローのモック」と明記します。

## 6. Pydantic AI買い物リスト整理

### 概要

「牛乳、パン、卵を買う」のような文章を品目と個数に分け、決められた型に合うか確認して買い物リストとして表示します。

### データの置き場所

- **入力例・期待する出力・異常系データ:** `pydantic-shopping-list`リポジトリの`tests/`にJSONで保存します。
- **作成したリスト:** 永続化が必要になった場合のみ、ローカルSQLiteまたはJSONに保存します。
- **APIキー:** `.env`で管理し、GitHubにはコミットしません。

```text
pydantic-shopping/
├── README.md
└── tests/
    ├── valid-inputs.json
    └── invalid-inputs.json
```

### 無料で作る範囲

まずはサンプル出力を使って、必須項目・型・不正な形式を検証するテストを作ります。ローカルモデルや利用可能な無料枠がある場合に、自然文からの生成を接続します。

## 共通の開発・データ管理方針

- GitHubには**架空または公開可能なサンプルデータ**だけを登録します。
- APIキーやパスワードは`.env`に置き、`.env.example`には変数名だけを書きます。
- `.env`、SQLiteファイル、実行ログ、キャッシュ、生成インデックスは`.gitignore`に追加します。
- DifyのナレッジベースやLlamaIndexのインデックスは、原本ではなく検索用データとして扱います。
- 最初はローカル実行を目標にし、外部公開や自動同期は必要になってから追加します。
- READMEには、実際に確認できた機能、モックを使った範囲、無料枠・ローカルモデルの制約を正直に記載します。
