# 無料で試すAIアプリポートフォリオ

Copilotを開発パートナーとして活用し、LLMアプリのフレームワークやライブラリーの特徴を、小さなアプリを通して学ぶポートフォリオです。

各アプリは**独立したプロジェクト／GitHubリポジトリ**として作成し、Docker環境も分けます。このREADMEはポートフォリオ全体の紹介用です。

まずは**追加費用をかけずにローカルで動くMVPを作る**ことを目標にします。LLM APIを使わないと動かない設計にはせず、ローカルモデルやモックデータでも基本機能を確認できるようにします。

> **開発状況:** 企画・設計段階。各アプリはこれから実装します。

## 1. Dify FAQボット

### 概要

架空の店舗やサービスについて、営業時間・返品ルール・問い合わせ先などのFAQを登録し、質問に回答します。資料に答えが見つからない場合は、推測せず「資料に情報がありません」と案内します。

### データの置き場所

- **原本:** `dify-faq-portfolio`リポジトリの`knowledge/`にMarkdownで保存し、GitHubで変更履歴を管理します。
- **検索用データ:** 原本をDifyのナレッジベースにアップロードします。
- **同期方法:** 最初は手動アップロードとし、資料を更新したらDify側も更新します。

```text
dify-faq-portfolio/
├── README.md
├── knowledge/
│   ├── shop-hours.md
│   ├── returns.md
│   └── contact.md
└── workflow/
    └── export.yml
```

### 無料で作る範囲

FAQを5〜10件に限定し、Difyの無料利用枠またはセルフホストを検討します。回答に使うLLMの料金は別になる場合があるため、利用するモデルと無料枠を事前に確認します。モック資料には架空の情報だけを使います。

## 2. LlamaIndexメモ検索アプリ

### 概要

短いメモをいくつか登録し、質問に関連するメモを検索して、根拠と一緒に回答します。関連する情報がない質問には回答を控えます。

### データの置き場所

- **原本・評価用質問:** `llamaindex-notes-search`リポジトリの`data/`と`tests/`に保存します。
- **検索インデックス:** ローカルで生成し、原本から再作成できるようにします。
- **会話履歴:** 必要になった場合のみ、ローカルのSQLiteに保存します。

```text
llamaindex-notes-search/
├── README.md
├── data/
│   └── notes/
│       ├── travel.md
│       └── study.md
└── tests/
    └── questions.json
```

### 無料で作る範囲

数件のテキストメモから始め、ローカルの埋め込み・LLMモデルまたは利用可能な無料枠を使います。大量のPDF解析やクラウド処理は初期版の対象外です。

## 3. LangChain家計CSV説明アプリ

### 概要

架空の家計簿CSVを読み込み、カテゴリ別の支出を集計します。「最も支出が多いカテゴリは？」などの質問に、集計結果をもとに回答します。

### データの置き場所

- **サンプルCSV・カテゴリ定義:** `langchain-budget-analyzer`リポジトリの`data/`に保存します。
- **集計結果:** 実行時に計算し、原則として永続保存しません。
- **ユーザーが追加した記録:** 保存が必要になった場合のみ、ローカルSQLiteを使います。

```text
langchain-budget/
├── README.md
└── data/
    ├── sample-expenses.csv
    └── categories.json
```

### 無料で作る範囲

金額計算はPythonなど通常のコードで行い、LLMには集計結果の説明だけを任せます。まずはサンプルCSVと固定文の説明で完成させ、無料で使えるローカルモデル等が利用できる場合に生成機能を追加します。個人の家計データはGitHubに置きません。

## 4. LangGraph○×クイズ

### 概要

問題に回答し、正解なら次の問題へ、不正解ならヒントを表示します。問題番号や正解数を保持します。

### データの置き場所

- **問題・正解・ヒント:** `langgraph-quiz`リポジトリの`data/questions.json`に保存します。
- **進行状況:** 簡単な試作ではメモリー上に保持し、再起動後も続ける場合はローカルSQLiteに保存します。

```text
langgraph-quiz/
├── README.md
└── data/
    └── questions.json
```

### 無料で作る範囲

問題は自作の固定データとし、LLMを使わずに状態遷移と分岐を実装します。まず「正解なら次へ、不正解ならヒント」の動きを確認します。

## 5. CrewAIお出かけプラン作成

### 概要

入力された条件を受けて、「行き先候補を出す役」と「候補を整理してプランにする役」が順番に作業します。

### データの置き場所

- **架空の候補地・条件:** `crewai-trip-planner`リポジトリの`data/`にJSONで保存します。
- **役割間の入出力・実行ログ:** ローカルに保存し、公開するデモ出力は個人情報を含まない内容にします。

```text
crewai-trip/
├── README.md
└── data/
    ├── destinations.json
    └── sample-requests.json
```

### 無料で作る範囲

まずは2役・小さな入力に限定します。ローカルモデルが使える環境なら接続し、難しい場合は固定応答でタスクの受け渡しを検証します。その場合、READMEに「実LLMによる生成ではなく、フローのモック」と明記します。

## 6. Pydantic AI買い物リスト整理

### 概要

「牛乳、パン、卵を買う」のような文章を品目と個数に分け、決められた型に合うか確認して買い物リストとして表示します。

### データの置き場所

- **入力例・期待する出力・異常系データ:** `pydantic-shopping-list`リポジトリの`tests/`にJSONで保存します。
- **作成したリスト:** 永続化が必要になった場合のみ、ローカルSQLiteまたはJSONに保存します。
- **APIキー:** `.env`で管理し、GitHubにはコミットしません。

```text
pydantic-shopping/
├── README.md
└── tests/
    ├── valid-inputs.json
    └── invalid-inputs.json
```

### 無料で作る範囲

まずはサンプル出力を使って、必須項目・型・不正な形式を検証するテストを作ります。ローカルモデルや利用可能な無料枠がある場合に、自然文からの生成を接続します。

## 共通の開発・データ管理方針

- GitHubには**架空または公開可能なサンプルデータ**だけを登録します。
- APIキーやパスワードは`.env`に置き、`.env.example`には変数名だけを書きます。
- `.env`、SQLiteファイル、実行ログ、キャッシュ、生成インデックスは`.gitignore`に追加します。
- DifyのナレッジベースやLlamaIndexのインデックスは、原本ではなく検索用データとして扱います。
- 最初はローカル実行を目標にし、外部公開や自動同期は必要になってから追加します。
- READMEには、実際に確認できた機能、モックを使った範囲、無料枠・ローカルモデルの制約を正直に記載します。
